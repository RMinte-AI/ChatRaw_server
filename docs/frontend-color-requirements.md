# ChatRaw 前端配色要求

本文件定义当前四页式产品界面的颜色基线。它约束 ChatRaw Core、Resident Integration 和在 Host Workspace 中运行的 Plugin；视觉实现以 `backend/static/styles.css` 中的 `--hub-*` 变量为代码事实源。

## 1. 设计目标

- 只提供浅色界面，不新增主题切换或私有深色分支。
- 以暖灰纸面、白色内容面和近黑文字建立层级；颜色用于表达分类、状态和操作，不用于装饰性渐变。
- 首页、内容页、Agent 和设置页使用同一组语义颜色。业务插件不得覆盖 Host 根变量，也不得用品牌色重绘 Host 导航。
- 正文和交互文字相对背景的对比度至少为 WCAG AA `4.5:1`；大号文字至少为 `3:1`。焦点、错误和可用状态不能只靠颜色表达。

## 2. 核心色板

| Token | 色值 | 用途 | 禁止用途 |
|---|---|---|---|
| `--hub-paper` | `#f7f6f3` | 页面底色、设置内容底色、Agent 展开态 | 卡片与页面同时使用，导致层级消失 |
| `--hub-surface` | `#ffffff` | 卡片、浮层、输入容器 | 大面积替代纸面底色 |
| `--hub-ink` | `#111111` | 标题、正文、主按钮；在纸面上对比度 `17.47:1` | 次要提示或禁用态 |
| `--hub-muted` | `#726f69` | 正常字号的辅助说明；在纸面上对比度 `4.63:1` | 禁用态以外的更浅正文 |
| `--hub-line` | `#e7e4de` | 边框、分隔线 | 单独表达选中、错误或焦点 |
| `--hub-green` | `#dde9db` | 分类卡片图标底色 | 正文、成功文字 |
| `--hub-blue` | `#dcecf4` | 分类卡片图标底色 | 链接或主操作文字 |
| `--hub-sand` | `#f3e6c4` | 分类卡片图标底色 | 警告状态 |

分类色只作为低饱和背景，图标和文字仍使用 `--hub-ink`。卡片按砂色、蓝色、绿色循环不承载固定业务语义；业务状态必须同时提供文字。

## 3. 交互与状态色

| 语义 | 前景 | 背景/边框 | 要求 |
|---|---|---|---|
| 选中、开关、键盘焦点 | `#315f3a` | `#edf4ec` / `#dfeade` | 焦点必须保留 2px 轮廓；选中态同时使用字重或图标 |
| 可用状态文字 | `#3d7147` | `#edf4ec` | 对比度 `5.14:1`，必须有状态文案 |
| 危险操作 | `#8e3f38` | `#f9ecea` / `#edd3cf` | hover 使用 `#74312c`、`#f5dfdc`；不得复用为普通强调 |
| 主操作 | `#ffffff` | `#111111` | 仅用于页面主动作；同一区域避免多个同级主按钮 |
| 次操作 | `#111111` | transparent / `#d9d5ce` | hover 可切换为白色表面，不加彩色阴影 |
| 禁用 | 继承当前前景 | 当前背景，整体 `opacity: .45` | 必须同时设置 `disabled` 和 `not-allowed`，不能只降低颜色对比 |

## 4. 实现规则

1. Core 新代码优先使用 `--hub-*` 语义变量；重复出现的硬编码色值必须收敛为变量。
2. Plugin 和 Resident 的选择器必须限定在自己的根节点内。可以读取公开的 Host 颜色变量作为回退，但不能修改 `:root`、`body` 或 `[data-theme]`。
3. 不使用渐变、霓虹、高饱和大色块、彩色投影或透明玻璃叠层。阴影只表达浮层高度，不能替代边框和焦点。
4. 新增颜色前必须说明现有语义色不能覆盖的原因，并同时补充本文、CSS token 和前端测试。
5. 截图比对不能替代对比度检查。至少验证默认、hover、focus-visible、disabled、success 和 danger 六种状态。

## 5. 验收

前端改动至少运行：

```bash
npm run build:frontend
npm run check:frontend
npm run test:frontend
```

审查时同时确认：页面没有可见深色主题入口；首页分类色不承担状态含义；Plugin/Resident 没有覆盖 Host 根色板；正常字号文字对比度不低于 `4.5:1`。
